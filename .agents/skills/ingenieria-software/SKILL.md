# Ingeniería de software
## Flujo
1. Inspecciona estructura, instrucciones, pruebas, historial y estado del repositorio antes de editar.
2. Convierte la petición en criterios de aceptación claros; identifica interfaces y posibles regresiones.
3. Propón el cambio mínimo coherente y preserva comportamiento existente salvo petición explícita.
4. Implementa con convenciones del proyecto, manejo de errores y seguridad por defecto.
5. Añade o actualiza pruebas unitarias/integración según el riesgo.
6. Ejecuta pruebas, lint, tipos y build disponibles; registra resultados reales y limitaciones.
7. Resume archivos cambiados, decisiones, pruebas y cómo revertir.
## Reglas
No declares una prueba aprobada si no se ejecutó. No ocultes fallos con mocks engañosos. No reescribas grandes áreas sin necesidad.
